### File Structure

The correct file structure for flower recognition:

```
backend/downloaded_model/
├── flower_best_model.keras           # Best model from training (via ModelCheckpoint)
├── flower_class_names.json           # Maps model indices to class IDs
├── classes_to_name_dictionary.json   # Maps class IDs to flower names
└── flower_training_config.json       # Training metadata
```

### Two-Step Mapping Process

The flower recognition uses a two-step mapping:

1. **Model Output → Class ID**: `flower_class_names.json`
   ```json
   {
     "0": "1",      // Model index 0 → Class ID "1"
     "1": "10",     // Model index 1 → Class ID "10"
     "2": "100"     // Model index 2 → Class ID "100"
   }
   ```

2. **Class ID → Flower Name**: `classes_to_name_dictionary.json`
   ```json
   {
     "1": "pink primrose",
     "10": "globe thistle",
     "100": "blanket flower"
   }
   ```

### Why Two Files?

The training script (`flower_model_training_script.py`) generates:
- `flower_class_names.json`: Because the dataset uses numeric folder names (1, 10, 100, etc.)
- `classes_to_name_dictionary.json`: Provides human-readable names for these class IDs

This is different from plant and architecture models which have direct name mappings.

## Frontend Integration

### API Response Format

The backend returns predictions in this format:

```json
{
  "success": true,
  "predictions": [
    {
      "class_id": "74",
      "flower_name": "rose",
      "confidence": 0.95,
      "confidence_percentage": 95.0
    }
  ],
  "top_prediction": {
    "class_id": "74",
    "flower_name": "rose",
    "confidence": 0.95,
    "confidence_percentage": 95.0
  }
}
```

### Frontend Usage

The frontend components (`Guest_ViewSummaryPage.jsx`, `User_ViewSummaryPage.jsx`) access the data as:

```javascript
const topPrediction = predictionData?.top_prediction || null;
const objectName = topPrediction?.flower_name || "Unknown Plant";
const confidence = topPrediction?.confidence_percentage || 0;
```

No changes were needed in frontend files as they correctly use the API service layer.

## Important Notes

1. **Best Model**: The training script uses `ModelCheckpoint` to save the best model during training to `flower_best_model.keras`. This is the model that should be used in production, not `flower_img_classifier.keras` (which is the final model after all epochs).

2. **Class Names File**: The correct file is `flower_class_names.json` (generated by training script), not the generic `class_names.json` that was being used before.

3. **No Output Model Folder**: The `/src/output_model/` folder was removed and no references to it exist in the codebase. This is safe.

4. **Firebase Storage**: When deploying, ensure Firebase Storage has:
   - `flower_best_model.keras`
   - `flower_class_names.json`
   - `classes_to_name_dictionary.json`
